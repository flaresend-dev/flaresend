<Endpoint method="POST" path="/v1/broadcasts/:id/send" />

<ApiPage>
<ApiMain>

Moves a `draft` broadcast to `sending`, or to `scheduled` when you pass `scheduledAt`. The response comes back straight away; the emails go out in the background.

## How sending works

The mailer's cron runs every 5 minutes. On each run it:

1. Moves `scheduled` broadcasts whose `scheduledAt` has passed to `sending`.
2. Takes up to 10 `sending` broadcasts and, for each one, the next 100 contacts in the audience.
3. Skips contacts that are unsubscribed or on the [suppression list](/docs/deliverability/suppressions).
4. Sends every other contact their own email, rendered with the [per-contact variables](/docs/api-reference/broadcasts/create#per-contact-variables).
5. Marks the broadcast `sent` once a run finds fewer than 100 contacts left.

So a broadcast to 500 contacts takes about five cron runs, around 25 minutes. The first emails go out on the next run after this call, up to 5 minutes later.

Each email:

- goes through the same path as [Send an email](/docs/api-reference/emails/send), so it counts toward the project's rate limit and daily limit;
- has the tag `broadcast_id` set to the broadcast ID;
- has the idempotency key `bc:<broadcast id>:<contact id>`, so a contact never gets the same broadcast twice;
- has `List-Unsubscribe` and `List-Unsubscribe-Post: List-Unsubscribe=One-Click` headers when the mailer has a `TRACKING_SECRET`. See [Unsubscribe](/docs/contacts/unsubscribe).

If a send hits a rate limit, the run stops there and the next run picks up from the same contact. Any other error on one contact is logged and that contact is skipped.

<Callout type="warn" title="Always live">
  Broadcasts always send real email, even when you call this endpoint with an `fs_test_` key. Test keys only change what `POST /v1/emails` does.
</Callout>

## Path parameters

<Fields>

<ParamField path="id" type="string" required>
  The broadcast ID.
</ParamField>

</Fields>

## Body parameters

The body is optional.

<Fields>

<ParamField body="scheduledAt" type="string">
  An ISO 8601 date-time with a time zone offset, in the future and at most 30 days ahead. The broadcast starts on the first cron run at or after this time.
</ParamField>

</Fields>

## Response

The broadcast with `counts`, as in [Retrieve a broadcast](/docs/api-reference/broadcasts/retrieve#response). `status` is `sending` or `scheduled`. `total` is the number of subscribed contacts in the audience right now; suppressed contacts are still in this number and are skipped later.

## Errors

| Status | Code | When |
|---|---|---|
| 400 | `invalid_body` | The body is not valid JSON, or the audience has no subscribed contacts. |
| 400 | `invalid_schedule` | `scheduledAt` is not a valid date, is in the past, or is more than 30 days ahead. |
| 400 | `too_many_recipients` | The audience has more subscribed contacts than `BROADCAST_MAX_RECIPIENTS` (default 500). |
| 403 | `broadcasts_disabled` | The project doesn't have broadcasts enabled. |
| 404 | `broadcast_not_found` | No broadcast with that ID in this project. |
| 409 | `broadcast_not_draft` | The broadcast was already started, sent or canceled. |

<ApiExample title="Request">

```ts tab="Node.js" tab-group="lang"
import { Flaresend } from '@flaresend/client';

const flaresend = new Flaresend({
  apiKey: process.env.FLARESEND_API_KEY!,
  baseUrl: 'https://mailer.example.com',
});

// Start now
await flaresend.broadcasts.send('bc_01K6C3D9G2J4L7N0Q3S5U8W1YZ');

// Or schedule it
await flaresend.broadcasts.send('bc_01K6C3D9G2J4L7N0Q3S5U8W1YZ', {
  scheduledAt: '2026-10-01T09:00:00Z',
});
```

```bash tab="cURL" tab-group="lang"
curl -X POST https://mailer.example.com/v1/broadcasts/bc_01K6C3D9G2J4L7N0Q3S5U8W1YZ/send \
  -H "Authorization: Bearer $FLARESEND_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "scheduledAt": "2026-10-01T09:00:00Z" }'
```

</ApiExample>
