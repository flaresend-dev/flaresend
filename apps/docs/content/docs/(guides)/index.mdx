Flaresend gives your apps a Resend-style email API on top of [Cloudflare Email Service](https://developers.cloudflare.com/email-service/). You deploy one Worker, and every app you run sends through it: other Workers call it over a service binding, and everything else calls a REST API with a project key.

Every send is logged, retried on failure, tracked through delivery, and reported back to you with signed webhooks. Nothing leaves your Cloudflare account.

## Send in one call

```ts tab="Node.js" tab-group="lang"
import { Flaresend } from '@flaresend/client';

const flaresend = new Flaresend({
  apiKey: process.env.FLARESEND_API_KEY!,
  baseUrl: 'https://mailer.example.com',
});

await flaresend.emails.send({
  from: 'Acme <hello@acme.com>',
  to: 'ada@example.com',
  subject: 'Hello from Flaresend',
  html: '<p>It works.</p>',
});
```

```bash tab="cURL" tab-group="lang"
curl -X POST https://mailer.example.com/v1/emails \
  -H "Authorization: Bearer $FLARESEND_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "from": "Acme <hello@acme.com>",
    "to": "ada@example.com",
    "subject": "Hello from Flaresend",
    "html": "<p>It works.</p>"
  }'
```

```ts tab="Worker (RPC)" tab-group="lang"
import { rpcClient } from '@flaresend/client/rpc';

const mail = rpcClient(env.MAILER, { project: 'acme' });

await mail.send({
  from: 'Acme <hello@acme.com>',
  to: 'ada@example.com',
  subject: 'Hello from Flaresend',
  html: '<p>It works.</p>',
});
```

`https://mailer.example.com` stands for the URL of your own mailer Worker. Flaresend is not a hosted service: you [deploy it](/docs/self-hosting/deploy) once, then point every app at it.
